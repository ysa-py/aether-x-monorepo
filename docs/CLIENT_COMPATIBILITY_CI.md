# External client parser validation contract

A serializer test is not client compatibility. This contract defines the narrow
claim made only after the CI test
`TestExternalClientParsersAcceptGeneratedSubscriptionConfigs` passes.

## Pinned parser binaries

| Client/core | Pinned release | CI action | Claim after a green CI run |
| --- | --- | --- | --- |
| sing-box | `v1.13.14` | Downloads the upstream Linux AMD64 release asset, verifies its GitHub release-asset SHA-256, then runs `sing-box check -c` on JSON emitted by `BuildSubscriptionBodyEx(..., "singbox")`. | That pinned sing-box binary accepts the generated VLESS-over-WebSocket JSON syntax. Not an end-to-end proxy connection claim. |
| Mihomo / Clash Meta | `v1.19.29` | Downloads the upstream compatible Linux AMD64 release asset, verifies its GitHub release-asset SHA-256, then runs `mihomo -t -f` on YAML emitted by `BuildSubscriptionBodyEx(..., "clash")`. | That pinned Mihomo binary accepts the generated VLESS-over-WebSocket YAML syntax. Not an end-to-end proxy connection claim. |
| Xray-family VLESS URI | no CLI subscription-import validator | The same test parses the URI emitted by `BuildProxyLink`, validates an RFC UUID, endpoint, and required VLESS/TLS/WebSocket query fields. | **Structural URI serialization only.** It is not an Xray-core parser or connection proof. |

The validation fixture uses documentation-range address material and does not
attempt a remote connection. It exercises actual bytes generated by
`control-plane/internal/subendpoint/config_builder.go`, rather than a checked-in
handwritten config.

## Explicit non-claims

- Xray-core does not expose a CLI mode which imports and validates a VLESS
  subscription URI. `xray run -test` validates native JSON configuration, not a
  share URI. It remains structurally serialized until a dedicated upstream
  importer/parser test is available.
- sing-box and Mihomo parser acceptance does not validate a mobile app,
  deep-link handler, server implementation, certificate, route, or censorship
  resistance.
- NekoBox, Shadowrocket, v2rayNG, Hiddify, Karing, FlClash/ClashX, v2RayTun,
  and Streisand remain unproven by this CI test.

A release update must change the binary URL and its SHA-256 in the test through
a reviewable PR; it must never use an unpinned `latest` binary.
